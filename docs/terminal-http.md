# HTTP Terminal and Lua editor

With Lua and the Program Manager enabled, `GET /api/program/output?boot_id=0&execution_id=0&cursor=0&limit=256` reads a non-destructive snapshot. All parameters except `limit` are required canonical unsigned decimals; `limit` is 1–256. Each reader tracks its own cursor; the route is absent when the runtime is disabled.

The response includes `boot_id`, `execution_id`, `cursor`, `next_cursor` and `lost` as decimal strings, plus `changed`, `reset`, `exhausted`, `encoding: "base64"` and `data`. A future cursor returns 409, invalid query 400, unavailable service 503. The 2 KiB ring is cleared on a new run and is not persistent. A read copies at most 256 bytes without holding the lock during network transmission. The browser incrementally decodes bytes and inserts text without interpreting HTML; it keeps at most 65,536 UTF-16 units and indicates lost output.

Polling uses one request at a time every 500 ms while LAB is visible, a 4 s timeout and a 5 s retry after errors; 404 suspends polling until returning to the view. There is no terminal input, WebSocket or automatic RUN retry. Lua files up to 50,000 characters receive local syntax highlighting; larger files remain editable without it. HTTP is unauthenticated and unencrypted; use a trusted network. Lua is not a complete sandbox.

Test host esercitano query invalide, cursori, dati binari, Base64, cambio esecuzione, reset, lettori concorrenti e lettura non distruttiva. Firefox headless su server simulato verifica polling, riconnessione, UTF-8 diviso, NUL, HTML ostile, perdite, limite DOM, runtime assente e regressioni Execution/ETag. Nella sessione misurata l'evidenziazione ha impiegato circa 5/16/101/15 ms per 1/10/50/100 KiB; oltre 50.000 caratteri è disabilitata. Sono misurazioni puntuali e non sostituiscono una valutazione interattiva su tutti i browser.

Su ESP32 Classic sono stati verificati Hello, output progressivo, ciclo infinito e STOP, sleep, errori sintattici/runtime, OOM e recupero, cambio RUN, deduplicazione e lettura dopo disconnessione. Con output continuo sono stati prodotti almeno 9.513.025 byte: il lettore rimasto indietro ha rilevato 10.522.394 byte persi, STOP è tornato a IDLE e health, STATUS e File Manager sono rimasti raggiungibili. Firefox sulla scheda ha visualizzato output, modificato e salvato esattamente testo Unicode, eseguito il file e verificato che un conflitto ETag impedisse il RUN. Nessun reset successivo all'avvio o panic è comparso nel monitor seriale. Si tratta di una singola campagna, non di una garanzia di assenza di perdite di memoria.
