# Web Settings: Wi-Fi

SYSTEM → Settings → Configure device opens Network. The access point is read-only; station credentials are optional. Press Scan networks to scan once, select a network or enter an SSID manually, choose whether to keep the saved password, replace it, or use an open network, then Save & Apply. Disabling station saves AP mode without deleting its credentials. Reconnect to the ZamproLab AP if the station address becomes unavailable. Temporary radio interruptions can occur when the shared radio changes channel or scans.

The AP can be used without a router: connect a client to ZamproLab's AP and open `http://192.168.4.1/`. Disabling STA in Settings persists AP mode; the serial command `wifi disconnect` instead temporarily suspends connection attempts without changing the saved mode. If a configuration change makes STA unreachable, reconnect through the AP or use the serial console and `wifi status` to investigate. A rejected request reports an error; an interrupted connection can leave its outcome unconfirmed, so check the device state before retrying.

## Validation status

**WEB SETTINGS FUNCTIONALLY VALIDATED — ESP32 CLASSIC** for the intended educational use. The Web Settings implementation is complete. Relevant host tests passed, as did ESP32 Classic and ESP32-S3 builds with Lua enabled and disabled; build success does not establish S3 hardware validation.

On ESP32 Classic, LAB was reached through AP and STA and Wi-Fi scanning was verified on hardware. The user confirmed scanning and selection through AP and Wi-Fi configuration through the browser, including Save & Apply.

During a subsequent STA disable attempt, the user reported an accepted request, while the device status observed through STA still showed AP+STA and no recorded operation. This discrepancy was not confirmed as a defect; the disable result remains unconfirmed. Persistence after reboot, STA re-enablement and recovery after incorrect credentials are not fully documented as passed for Web Settings. A restart coincided with opening the serial console, after which STA reconnected; this observation does not replace a complete controlled persistence test.

HTTP is neither authenticated nor encrypted. A network client can call the APIs directly and read or modify files and execute programs; use only trusted networks and never expose the device to the Internet. Host/Origin checks for the new Wi-Fi POST routes reduce browser cross-origin requests; they are not authentication. Open the LAB using the device's literal IPv4 address over HTTP; DNS names, IPv6, proxies and nonmatching ports/origins are not supported for Wi-Fi changes. The existing AP password is a shared educational default; change it via the serial console.

The existing `GET /api/wifi/status` includes `sta_ssid_valid_utf8`, `last_error` and `disconnect_reason`. `GET /api/wifi/operation` returns a volatile `boot_id`, `next_id`, and the most recent operation if present; `?id=N` selects its result. `POST /api/wifi/settings` accepts JSON `boot_id`, `operation_id`, `enabled`, optional `confirm_sta_only`, and for enabled station `ssid` and `password_action` (`keep`, `replace`, `open`); `password` is supplied only for `replace`. Accepted means queued, not saved. Persistence, driver application and connection are separate stages. IDs are strictly increasing within a boot; old IDs and different boot IDs are rejected. An uncertain request must not be retried automatically, particularly after reboot. An HTTP failure after acceptance can leave the outcome unknown.

`POST /api/wifi/scan` accepts an empty body and starts a scan; `GET /api/wifi/scan?id=N` returns its boot ID, pending flag, error and up to 20 results. Empty SSIDs are hidden networks. Non-UTF-8 SSIDs are labelled and cannot be selected; enter the intended SSID manually. No scan writes NVS. A scan timeout can leave the scanner unavailable until the late driver event is received; if it never arrives a reboot may be needed.

Wi-Fi POST requests require the literal local IPv4 Host and corresponding Origin, a bounded JSON body where applicable, and complete reads. SSIDs accept 1–32 UTF-8 bytes without control bytes; passwords are empty for open networks or 8–63 printable ASCII characters. Unicode JSON escapes are not accepted; browsers send UTF-8 directly. Passwords are not returned, logged or intentionally stored in browser storage. The current firmware stores Wi-Fi credentials in an unencrypted NVS record; physical flash access is outside this feature's protection.
